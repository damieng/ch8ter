# Test fixtures

Real files used by the test suite. Kept in the repository so tests do not need
network access, and so a failure means the parser changed rather than the
upstream file did.

Prefer real output from real tools over anything generated by this codebase,
and record the source and licence below. Files produced by our own writers
belong in a test, not here: they can only confirm that the writer and reader
agree with each other.

## `ttf/` — 4 files, ~9 KB

The two bitmap-only TrueType reproducers from
[thorvg issue #4945](https://github.com/thorvg/thorvg/issues/4945), built from
scratch with fontTools 4.67.0. Released **CC0 1.0** (no rights reserved), and
they contain no third-party font data.

| File | Layout | Tables |
| --- | --- | --- |
| `bitmap-opentype.ttf` | OpenType | `EBDT EBLC OS/2 cmap head hhea hmtx maxp name post` |
| `bitmap-apple.ttf` | Apple | `OS/2 bdat bhed bloc cmap maxp name post` |

Both carry one 16 ppem, 1-bit strike with `.notdef`, space, `A` and `B`
(cmap: U+0020, U+0041, U+0042). `README.txt` and `build_repro.py` are the
originals from the archive and document how they were generated.

At ~1.3 KB each they are the smallest useful embedded-bitmap fonts available,
and being generated by an independent tool they test the reader rather than my
understanding of the format. They are also the reason the Apple `'true'` sfnt
version is now accepted: the table walk already handled `bloc`/`bdat`, but the
entry point rejected that version, leaving the path unreachable.

## `cpi/` — 2 files, ~3.5 KB

A `.cpi` font plus the same font packed as a `.cpx`, generated **by this
project**, so no third-party code or data is involved:

```
pnpm tsx scripts/make-cpx-fixture.ts
```

- `sample.cpi` — 256 glyphs of 8x8 written by our own `cpiWriter`, filled with
  a simple gradient (no copyrighted glyph shapes).
- `sample.cpx` — the same CPI packed with **UPX 3.96** into a DOS COM.

The second one requires a UPX that still packs DOS COM files: 4.x and 5.x
dropped the format, and FreeDOS's real CPX files were made with UPX 1.x. Set
`UPX_BIN` to such a binary. The packed output is committed, so the script only
needs re-running if the CPI writer's layout changes.

A CPX cannot be synthesised in code — `cpxDecoder` works by emulating the UPX
decompression stub — so this generated file is the only way to test that path
without vendoring a GPL-2 CPX from FreeDOS (this project is MIT).

## Adding fixtures here

Keep files small (a few KB where possible), verify the licence permits
redistribution, and add a row or section above with the source, tool and
licence. Anything generated by our own code should note the script that
regenerates it.
